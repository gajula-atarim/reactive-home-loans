01 — Executive summary

A small, clean site. Security comes first.

Structurally this is a tidy website. The crawl found 9 HTML pages, short and readable web addresses, no broken internal pages, no server errors and no duplicate page titles. Google's PageSpeed Insights gives it an SEO score of 92/100 on mobile. That is a good starting point.

The biggest problem is security and trust. Screaming Frog found 39 URLs still on insecure HTTP, and one form sits on an HTTP page and sends its data to an HTTP address. For a finance business whose visitors enter personal and financial details, this comes before any ranking work.

The next problem is how the site describes itself to search engines. 8 pages have no canonical tag and 1 points its canonical elsewhere. The Calculators page has no H1. Up to 4 pages have no meta description, and 2 titles are long enough to be cut off. Three pages carry only about 110–115 words.

None of this needs a rebuild. Most fixes are settings changes at the hosting, security plugin and SEO plugin level, and the critical items can be done in the first two weeks.

MOST URGENT

HTTPS is not enforced everywhere, including on a form

Screaming Frog reports 39 HTTP URLs (29.32% of all URLs), Form on HTTP URL (1) and Form URL Insecure (1). Anything typed into that form can be read in transit, and browsers label pages like this "Not Secure".

HIGHEST VOLUME

Almost half the pages give Google no canonical signal

8 pages (47.06%) have no canonical tag. With HTTP and HTTPS versions of URLs both reachable, Google has to guess which version is the master copy.

ALREADY STRONG

Status codes and URL structure need no work

There are no internal 4xx or 5xx errors and only 2 internal redirects. No URL-structure issues were flagged, there are no missing or duplicate titles, and no missing image alt text was reported. These areas can be left alone.

TECH-0139 URLs are still served over insecure HTTP

Critical

Screaming Frog found 39 HTTP URLs, which is 29.32% of everything it crawled. Browsers mark HTTP pages "Not Secure", HTTPS is a confirmed Google ranking signal, and when both versions of a page exist, link value is split between them.

The export doesn't say whether these URLs already redirect to HTTPS or are linked directly. That is shown in the Security › HTTP URLs Inlinks bulk export.

RECOMMENDED ACTION

Force HTTPS site-wide with a 301 redirect from HTTP to HTTPS, update every internal link, menu and image reference to HTTPS (a search-replace in WordPress), and then turn on HSTS.

TECH-02A form sits on an HTTP page and submits to an HTTP address

Critical

Two separate Screaming Frog checks fail on the same form: Form on HTTP URL and Form URL Insecure. For a business taking loan enquiries, the details typed in can include names, phone numbers and financial information. All of it is sent unencrypted.

RECOMMENDED ACTION

Identify the page (see Bulk Export › Security › Form URL Insecure), change the form's action URL to HTTPS, make sure the page itself only loads on HTTPS, and send a test enquiry to confirm submissions still arrive.

TECH-03Security response headers are missing on almost every URL

Low

CSP, X-Frame-Options, X-Content-Type-Options and Referrer-Policy are each missing on 130 URLs (97.74%), and HSTS is missing on 93 (69.92%). Google doesn't rank on these headers, but they protect visitors from clickjacking and injected scripts. HSTS also directly supports TECH-01.

RECOMMENDED ACTION

Set these headers once at server, CDN or security-plugin level, starting with HSTS after HTTPS is enforced. Test CSP carefully so the site's own scripts and forms keep working.

DATA GAP

Page speed was not measured in this export

The only performance-related finding is 2 images missing width/height attributes (section 12), which can cause layout shift. The export contains no response times, page weights or Core Web Vitals. The PageSpeed screenshot supplied covers the SEO category only. Run Lighthouse Performance on key pages to complete this baseline.

05 — Crawlability & indexability

What Google can reach, and what gets in its way

The export has no noindex, nofollow or robots.txt-blocked findings, so nothing appears to be excluded on purpose. Three things still get in the crawler's way.

CRAWL-01One internal URL returned no response at all

High

Screaming Frog's Internal No Response check failed on 1 URL (0.70%). The server returned nothing, which is usually caused by a malformed link, a timeout or a firewall blocking the request. Anyone who follows that link, visitor or crawler, hits a dead end.

RECOMMENDED ACTION

Export Response Codes › Internal › No Response inlinks to find the URL and the pages linking to it. Correct the link or the server rule, then re-test.

CRAWL-02The "Resources" menu item cannot be followed by search engines

High

PageSpeed Insights failed the Links are not crawlable check on <a aria-expanded="false" class="menu-link">, labelled "Resources". It has no href, so it opens a dropdown for visitors but gives search engines nothing to follow. It sits in the main navigation, so any page reached only through it is at risk of being missed.

RECOMMENDED ACTION

Point "Resources" to a real Resources page, or confirm that every page in its dropdown is also linked normally in the navigation or footer.

CRAWL-03The three legal pages have no internal links pointing to them

Medium

The supplementary audit flags these pages as orphans: they are known to exist but nothing on the site links to them. Screaming Frog cannot find a page like this by following links. For a finance business, the privacy policy and disclaimer are also trust and compliance pages that visitors expect to find.

Affected URLs/privacy-policy/ · /terms-and-conditions/ · /disclaimer/
RECOMMENDED ACTION

Add all three to the site footer. Then decide whether Terms and Disclaimer should be indexed at all (see DUP-01).

PAGE-01The Calculators page has no H1 and only 115 words

High

Calculators is a natural landing page for searches like "home loan repayment calculator", but it gives Google the least to go on. It has no main heading and 115 words of readable text. If the calculators are built in JavaScript, Google may see even less than a visitor does.

RECOMMENDED ACTION

CANON-01Eight pages give Google no canonical signal

High

A canonical tag tells Google "this address is the master copy of this page". Without one, Google picks its own. That is a real risk on this site because 39 HTTP URLs exist alongside their HTTPS versions, so the wrong version could be indexed or ranking signals split between the two.

RECOMMENDED ACTION

Turn on self-referencing HTTPS canonicals in the SEO plugin so every indexable page outputs one automatically. Then confirm in the re-crawl that the count reaches 0.

CANON-02One page tells Google to index a different URL

High

Screaming Frog classes 1 page as Canonicalised: its canonical points somewhere else, so it is excluded from search results. That is correct if it's a duplicate or HTTP variant. If it's a real page, it's being hidden from Google by mistake.

RECOMMENDED ACTION

Identify the URL from the Canonicals › Canonicalised filter. Correct the canonical if the page should rank. If it's a variant, update internal links to point at the canonical version.

IMG-01Two images have no width or height set

Low

Without dimensions, the browser can't reserve space for an image, so text jumps when it loads. This shows up as Cumulative Layout Shift (CLS), one of Google's Core Web Vitals.

RECOMMENDED ACTION

Add width and height attributes that match each image's real size. Most WordPress image blocks do this automatically, so the culprits are likely theme or builder images.

Everything found, in the order it should be fixed

15 — SEO action plan

An eight-week sequence, ordered by dependency

Security and indexing come first, so the on-page work that follows is credited to the right, secure URLs.

WEEK 1 · SECURE

Close the trust gap

  • Export the 39 HTTP URLs with their inlinks; force a 301 redirect from HTTP to HTTPS site-wide
  • Search-replace internal http:// links, menus and image references to https://
  • Move the insecure form to HTTPS (page and action URL) and send a test enquiry
  • Find and fix the internal URL that returns no response
  • Check robots.txt and the XML sitemap, neither of which was captured in this export
WEEKS 2–4 · FOUNDATIONS

Fix what every page depends on

  • Turn on self-referencing HTTPS canonicals; review the 1 canonicalised URL
  • Turn on HSTS once HTTPS is confirmed everywhere
  • Give the "Resources" menu item a real link
  • Add an H1 and supporting copy to Calculators
  • Write a meta description for Commercial Asset Finance and the 3 legal pages
  • Link the legal pages from the footer; decide on noindex for Terms and Disclaimer
  • Re-crawl to confirm the week 1 fixes registered
WEEKS 5–8 · OPTIMISE

Sharpen what is already working

  • Rewrite the Home and Loan Types titles to 50–60 characters
  • Trim the 1–3 over-length meta descriptions
  • Fix heading order on the 4 affected pages; make duplicate and missing H2s specific
  • Add anchor or alt text to empty links on 4 pages; add size attributes to 2 images
  • Point 2 internal links past their redirects; fix or remove 2 broken external links
  • Add CSP, X-Frame-Options, X-Content-Type-Options and Referrer-Policy headers; add rel="noopener" to new-tab links
ONGOING · MEASURE

Prove the work landed

  • Re-crawl monthly with identical Screaming Frog settings and compare against section 16
  • Run Lighthouse Performance on key pages to add Core Web Vitals to the baseline
  • Connect Google Search Console to track indexing, impressions and clicks
  • Re-run PageSpeed Insights SEO; target 100 once the menu link is fixed
